## Was ist NIP-05?

NIP-05 (Nostr Implementation Possibility #5) ermöglicht dir einen menschenlesbaren Identifier wie `du@domain.com` statt einer langen Zeichenkette aus zufälligen Zeichen.

### Das Problem, das es löst

<DiagramCompare
  panels={[
    {
      title: "Vor NIP-05",
      lines: ['Folgen: npub1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx', '"Hey, folge mir! Ich bin npub1abc123…xyz789"'],
    },
    {
      title: "Nach NIP-05",
      tone: "positive",
      lines: ['Folgen: alice@example.com', '"Hey, folge mir! Ich bin alice@example.com"'],
    },
  ]}
  caption="Dieselbe Identität, nur in einer Form, die ein Mensch tatsächlich laut vorlesen kann."
/>

### Was du bekommst

Eine Adresse, die man weitergeben kann. „Finde mich unter bob@nostrplebs.com“
übersteht es, auf einem Konzert laut gesagt, auf eine Karte gedruckt oder am
Ende einer Podcast-Folge vorgelesen zu werden. Sie wirkt gewählt statt generiert,
in den meisten Clients kann man dich danach suchen, und viele setzen ein kleines
Häkchen daneben. Was dieses Häkchen bedeutet, solltest du verstehen, bevor du
dich darauf stützt. Der Abschnitt über Vertrauen weiter unten sagt genau, was es
belegt und was nicht.

### Aber denk dran

> ⚠️ **NIP-05 ist optional.** Du kannst Nostr problemlos mit nur deinem npub nutzen.

Der NIP-05-Identifier ist eine **Bequemlichkeit**, keine Anforderung. Dein `npub` ist deine echte Identität auf Nostr.

## Warum NIP-05 verwenden?

### Einfacher zu teilen

```
Auf einer Party:
"Was ist dein Nostr?"

Ohne NIP-05:
"Äh... n-p-u-b-eins-x-x-x... lass mich auf meinem Handy suchen"

Mit NIP-05:
"Einfach alice@example.com"
```

### Professionelles Erscheinungsbild

- **Unternehmen**: `support@yourcompany.com`
- **Kreative**: `artist@yourdomain.com`
- **Entwickler**: `dev@opensourceproject.com`

### Vertrauen & Authentizität

Viele Clients zeigen ein ✓-Badge für NIP-05-Nutzer:

<MockProfile
  name="Alice"
  handle="alice@example.com"
  bio="Bitcoin Educator"
  verified
  caption="Eine verifizierte NIP-05-Adresse, so wie die meisten Clients sie darstellen."
/>

Dieses Badge belegt weniger, als es zu belegen scheint. Es sagt nur, dass die
Domain in der Adresse genau diesen Schlüssel für genau diesen Namen ausliefert.
Alles Weitere hängt an der Domain. `alice@alice.dev` wiegt schwer, weil Alice
alice.dev gehört und sonst niemand dort etwas veröffentlichen kann. `alice@` bei
einem offenen Gratis-Anbieter heißt nur, dass der Name frei war, als jemand
danach fragte, und ein Betrüger, der sich beim selben Anbieter `alicee@` holt,
bekommt ein identisches Häkchen neben seinen Namen.

Die Frage lautet also: Auf welche Domain zeigt das Badge? Erkennst du die Domain
als die eigene Seite der Person, bestätigt das Häkchen, dass der Schlüssel ihr
gehört. Ist es eine Domain, von der du nie gehört hast, sagt das Häkchen nichts
darüber, wer hinter dem Konto steckt.

### Brauchst du einen?

**Nein.** Du kannst Nostr problemlos ohne nutzen.

**Aber...** es ist sehr empfehlenswert, wenn du:

- Eine persönliche Marke aufbaust
- Inhalte erstellst
- Ein Unternehmen führst
- Nostr langfristig ernst nimmst
- Es leid bist, 63-Zeichen-Zeichenketten zu lesen

### Keine Zentralisierung!

Die Sorge ist berechtigt. Wenn dein Name auf der Domain eines anderen liegt, hast
du ihm dann deine Identität überlassen? Nein. Die Adresse ist ein Zeiger, gefolgt
wird dem npub. Du kannst mehrere Adressen gleichzeitig halten, eine auslaufen
lassen oder später auf deine eigene Domain umziehen, und deine Follower bleiben,
wo sie sind, weil sie dem Schlüssel gefolgt sind. Verlierst du die Adresse ganz,
verlierst du eine Bequemlichkeit. Konto, Posts und Follower bleiben unberührt.

## Deine eigene Domain verwenden

Für vollständige Kontrolle und Professionalität nutze deine eigene Domain.

### Schritt 1: Kaufe eine Domain

Jeder Domain-Registrar funktioniert:

- [Namecheap](https://namecheap.com)
- [Porkbun](https://porkbun.com)
- [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/)

Kosten: Normalerweise 10-15$/Jahr

Die Domain zu besitzen ist nur die halbe Miete. Du brauchst außerdem einen Ort,
der Dateien für diese Domain ausliefert, in der Praxis also das Webhosting, auf
dem deine Seite ohnehin läuft. Manche Baukästen (Squarespace, Wix, Substack und
ähnliche) lassen dich keine Datei in einem Ordner namens `.well-known` ablegen,
und aus ihrem Editor heraus führt daran kein Weg vorbei. Wenn deiner dazugehört,
nimm stattdessen einen kostenlosen oder bezahlten Anbieter. Für deine Leserinnen
und Leser funktioniert die Adresse genau gleich.

### Schritt 2: Erstelle die nostr.json-Datei

Hoste eine Datei unter `https://deinedomain.com/.well-known/nostr.json`:

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

Dein Identifier lautet dann: `alice@deinedomain.com`

<Callout variant="warning" title="Verwende deinen öffentlichen Schlüssel als Hex, nicht deinen npub">
  NIP-05 erwartet deinen öffentlichen Schlüssel als reines Kleinbuchstaben-Hex.
  Wenn du `npub1...` in `nostr.json` einträgst, schlägt die Verifizierung bei
  allen Clients fehl, und zwar stillschweigend, ohne Fehlermeldung.

Manche Clients zeigen die Hex-Form irgendwo in ihren Schlüssel-Einstellungen.
Zeigt deiner immer nur `npub1...`, füge das in das Prüfwerkzeug weiter unten auf
dieser Seite ein, das beide Formen nebeneinander anzeigt.

</Callout>

**Es sind keinerlei DNS-Einträge beteiligt.** Die NIP-05-Verifizierung ist eine
gewöhnliche HTTPS-Anfrage an `/.well-known/nostr.json`. Du brauchst weder einen
TXT-Eintrag noch einen CNAME noch sonst einen DNS-Eintrag über den hinaus, der
deine Domain bereits auf deinen Webserver zeigen lässt.

Zwei Servereinstellungen entscheiden darüber, ob Web-Clients die Datei überhaupt
lesen können, und beide scheitern lautlos, wenn sie falsch sind. Die Datei muss
mit dem Header `Access-Control-Allow-Origin: *` ausgeliefert werden, erst das
erlaubt einem Client im Browser, sie zu lesen; bei den meisten Hostern ist das
eine Zeile Konfiguration, und der Support trägt sie dir ein, wenn du genau danach
fragst. Außerdem muss die Adresse selbst antworten. Schickt `deinedomain.com`
Besucher weiter zu `www.deinedomain.com`, bricht die Verifizierung, denn Clients
müssen Weiterleitungen bei dieser Datei ignorieren. Welche der beiden du in
deiner NIP-05-Adresse führst, die muss die Datei direkt ausliefern.

### Beispiel-Setup Schritt für Schritt

**Szenario:** Du besitzt `alice.dev`

1. **Erstelle die JSON-Datei:**

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

2. **Lade sie auf deinen Server hoch:**

```
https://alice.dev/.well-known/nostr.json
```

3. **Überprüfe, ob es funktioniert:**
   Öffne im Browser: `https://alice.dev/.well-known/nostr.json`

4. **Füge es deinem Nostr-Profil hinzu:**
   In deinem Client: Einstellungen → Profil → NIP-05 → `alice@alice.dev`

### Überprüfe deinen Identifier

Nutze unser Tool unten oder rufe die Adresse deines Identifiers direkt auf:

<NIP05Checker showForm={true} client:idle />

### In deinem Client

Die meisten Clients zeigen den NIP-05-Status:

**Damus/Amethyst:**

- Einstellungen → Profil → NIP-05-Feld
- Zeigt ✓ wenn korrekt eingerichtet

**Primal:**

- Profil zeigt NIP-05-Badge
- Klicke Badge für Details

### Häufige Probleme beheben

Fang mit dem Prüfwerkzeug oben an. Gib `du@deinedomain.com` ein, und es zeigt
dir, was ein Client sieht, wenn er dich nachschlägt. Die Listen unten sagen, was
gegen die jeweiligen Antworten hilft.

**"NIP-05 funktioniert nicht"**

- **Prüfe zuerst das Schlüsselformat.** `nostr.json` muss deinen öffentlichen
  Schlüssel als Kleinbuchstaben-Hex enthalten, 64 Zeichen, ohne `npub1`-Präfix.
  Ein `npub` an dieser Stelle ist die mit Abstand häufigste Ursache für ein
  NIP-05, das nie verifiziert wird.
- Stelle sicher, dass das JSON valide ist (nutze einen JSON-Validator)
- Prüfe, dass die Datei unter der exakten URL erreichbar ist

**"Datei nicht gefunden"**

- Stelle sicher, dass der `.well-known`-Ordner erstellt ist
- Prüfe, ob dein Server versteckte Verzeichnisse ausliefert
- Verifiziere den Pfad: `/.well-known/nostr.json`

**"Domain löst nicht auf"**

- DNS-Änderungen können bis zu 24 Stunden dauern
- Lösche deinen DNS-Cache
- Optional, wenn du dich im Terminal wohlfühlst: `dig deinedomain.com` zeigt, ob der Name schon auflöst

**"Client erkennt es nicht"**

- Manche Clients cachen NIP-05-Lookup-Ergebnisse
- Versuche dich aus- und wieder einzuloggen
- Warte ein paar Minuten für die Propagierung

**"Verification Failed" Fehler**

**Mögliche Ursachen:**

1. **JSON-Syntaxfehler**: Prüfe auf fehlende Anführungszeichen oder Kommas
2. **Falscher Dateipfad**: Muss unter `/.well-known/nostr.json` sein
3. **Caching**: Warte 10-15 Minuten und versuche es erneut
4. **HTTPS erforderlich**: Muss über HTTPS ausgeliefert werden
5. **Fehlender CORS-Header**: Ohne `Access-Control-Allow-Origin: *` auf dieser Datei können Clients im Browser sie nicht lesen, auch wenn sie sich bei dir problemlos öffnet
6. **Eine Weiterleitung dazwischen**: Springt die Adresse von `deinedomain.com` auf `www.deinedomain.com` oder umgekehrt, ignorieren Clients die Weiterleitung und geben auf

**Lösung:**

- Validiere JSON auf jsonlint.com
- Prüfe, ob die Datei am exakten Pfad ist
- Lösche Client-Cache
- Stelle sicher, dass das SSL-Zertifikat gültig ist
- Bitte deinen Hoster, für diese Datei `Access-Control-Allow-Origin: *` mitzusenden
- Trag in deine NIP-05-Adresse den Hostnamen ein, der die Datei ohne Weiterleitung ausliefert

**"Not Found" Fehler**

**Mögliche Ursachen:**

1. Datei nicht am korrekten Ort hochgeladen
2. Server blockiert Punkt-Verzeichnisse
3. Falsche Domain

**Lösung:**

- Verifiziere, dass die Datei unter der exakten URL existiert
- Prüfe, ob `.htaccess` oder die Server-Konfiguration Punkt-Verzeichnisse erlaubt
- Bestätige, dass du die richtige Domain verwendest

**Anbieterspezifische Probleme**

**NostrPlebs:**

- Melde dich im Verwaltungsportal an und prüfe, ob der dort gespeicherte npub exakt deinem entspricht
- Stelle sicher, dass npub korrekt ist (nicht nsec!)
- Kontaktiere Support falls du feststeckst

**Self-hosted:**

- Nutze das Prüfwerkzeug oben; es sagt dir, ob die Datei erreichbar ist und ob der Schlüssel darin deiner ist
- Stelle sicher, dass Dateiberechtigungen Lesen erlauben
- Sieh in die Server-Logs, falls du Zugriff darauf hast

<Callout variant="warning">
  Teile niemals deinen nsec (privaten Schlüssel) beim Einrichten von NIP-05. Nur dein npub
  (öffentlicher Schlüssel) wird benötigt.
</Callout>

## Fortgeschrittene Tipps

### Mehrere Identitäten

Du kannst mehrere NIP-05-Adressen haben:

```
persoenlich@deinedomain.com
arbeit@deinedomain.com
blog@deinedomain.com
```

Alle zeigen auf denselben npub, oder verschiedene.

### Subdomains

Nutze Subdomains zur Organisation:

```
alice@team.deinedomain.com
alice@community.deinedomain.com
```

### Mehrere Nutzer hosten

Du kannst mehrere NIP-05-Identifier auf einer Domain hosten:

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9",
    "bob": "3bf0c63fcb93463407af97a5e5ee64fa883d107ef9e558472c4eb9aaaefa459d",
    "carol": "82341f882b6eabcd2ba7f1ef90aad961cf074af15b9ef44a09f9d2a8fbfbe6a2"
  }
}
```

### Dein Setup verifizieren

**Methode 1: Dein Client**

1. Füge das NIP-05 zu deinem Profil hinzu
2. Speichere Änderungen
3. Suche nach einem Häkchen ✓ oder "verifiziert" Badge
4. Kann ein paar Minuten zur Propagierung dauern

**Methode 2: Nostr-Explorer**

1. Öffne `njump.me/deinname@deinedomain.com` im Browser
2. Kommt dein Profil, löst dein NIP-05 auf deinen Schlüssel auf

**Methode 3: Direkter Test (Kommandozeile, optional)**

```bash
curl https://deinedomain.com/.well-known/nostr.json
```

**So sieht Erfolg aus:**

- ✅ Client zeigt Verifizierungs-Badge
- ✅ Andere können dich über dein NIP-05 finden
- ✅ Dein Profil zeigt deinen menschenlesbaren Namen

### Datenschutz-Überlegungen

Eine NIP-05-Adresse bindet deinen Schlüssel an eine Domain, und eine Domain kann
jeder nachschlagen. Läuft sie auf deinen Namen, oder trägt die Seite darauf
ohnehin schon deine Biografie und deine Fotos, verbindet die Adresse ganz
nebenbei ein pseudonymes Konto mit dem Rest deines Lebens. Manchmal ist genau das
der Zweck. Wenn nicht, lass das pseudonyme Konto auf der Domain eines kostenlosen
Anbieters und heb deine eigene Domain für die Arbeit auf, unter die du gern
deinen Namen setzt.
